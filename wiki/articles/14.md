1. Import this project in your desired instance.
2. In the home page of the project, click on  **PROJECT SETUP**.

### Configure your audit logs ingestion
3. Choose the logs origin.
  - For log4j logs, select *log4j logs*.
  - For Cloud instances, select *Cloud logs*.
  - For self-hosted Dataiku instance with [Event Server configured](https://doc.dataiku.com/dss/latest/operations/audit-trail/eventserver.html), select *Event Server logs*.
4. Choose the connection where logs are available.
  - For log4j logs, select the connection from which you can have [access to the audit logs](https://doc.dataiku.com/dss/latest/operations/audit-trail/centralization-and-dispatch.html#log4j-target).
  - For Event Server, select the connection you configured where Event Server logs are dumped.
  - For Cloud instances, select **dku-audit-log**.
5. Configure partitioning.<br/>
  - **We strongly suggest configuring it if you decide to continuously process incoming audit logs.**
  - For log4j, you can choose the time partitioning (year, month, day, hour).
  - For Event Server, you can choose the time partitioning (year, month, day, hour).
  - For Cloud logs, the default is day partitioning.
  - So for example, if you configured your Event Server with time partition "day", you can in the project setup:
      - Enable partitioning
      - Choose "Day" as period
      - Fill in %Y/%M/%D/.* as pattern
6. Select the connection that will be used by intermediate managed datasets in the flow. 
  - It can be on the same connection as the audit logs or a different one. 
  - For Cloud, you will want to choose **dataiku-managed-storage** for example, as **dku-audit-log** is not writable.
7. Click on the  **RECONFIGURE**  button to update the flow according to your selections.

### Fill in your audit log path
8. Configure the path where the logs are.
  - For log4j, click on [audit_logs](dataset:audit_logs) and specify either the root path or the year or the month depending on your needs.
  - For Event Server, click on [eventserver_cru_logs](dataset:eventserver_cru_logs) and specify either the root path or the year or the month depending on your needs.
  - For Cloud instances, click on [compute_resource_usage_logs](dataset:compute_resource_usage_logs) dataset  to set */audit-logs/* as log path. 
  - **If you enabled partitioning**, you want the path to be just before the year part.
      - Given this structure ```/event-server/compute-resource-usage/{node}/{year}/{month}/{day}/{hour}/*```, the configured path should be ```/event-server/compute-resource-usage/{node}```
9. Click on SAVE and go back to the **PROJECT SETUP**.

### Build your audit logs
10. **If you enabled partitioning**, fill in a date range. This date range will be taken into account to build historical logs.
11. Click on the **APPLY AND BUILD** button. It can take several minutes to hours, depending on the amount of logs available.

### Configure budget monitoring
12. Fill in budget rules in the [budget](dataset:budget) dataset. Check the [Configuring budget rules](article:28) article.
13. If you wish, you can activate continuous build. It will monitor the input dataset for any new audit logs and trigger a rebuild and a reevaluation of budget rules.
14. If you activated the continuous build, you can fill in the ID of a [messaging channel](https://doc.dataiku.com/dss/latest/scenarios/reporters.html) so alerts are sent when projects reach budget milestones.
15. Finally click on **APPLY** to apply your changes.
